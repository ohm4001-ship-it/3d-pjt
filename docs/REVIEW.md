# Formworks 기술 리뷰

작성일: 2026-10-14 · 대상: 로컬 단일 사용자 MVP

이 문서는 시니어 개발자의 설계·검증 기준으로 작성했다. 소스, 데이터 흐름, 테스트의 검증 범위를 근거로 평가하며 실제 추론·브라우저 실행 결과는 검증 보고서와 구분한다.

## 판단

포트폴리오의 첫 구현으로 방향은 타당하다. 입력 → 확인한 규격 → 3D → BOM·견적 → 변경 이력 → 승인·발주 기록으로 이어지는 업무 흐름이 있고, 금액과 상태를 서버가 관리한다. AI 결과를 제조 치수로 취급하지 않는 경계도 적절하다.

현재 단계에서 설명할 수 있는 제품은 **모듈형 진열대의 사양 확인과 예상 견적을 지원하는 로컬 업무 도구**다. 제조 가능한 도면 생성, 실제 고객의 승인, 공급사 발주, ERPNext 연결은 구현·검증 범위에 포함되지 않는다. 기능 수보다 이 경계를 명확히 설명하는 편이 면접에서 설득력이 있다.

실제 제작업체의 문제가 검증됐다는 근거는 아직 없다. “3D 확인이 요구사항 왕복을 줄이고, 변경 시 BOM·견적을 다시 쓰는 시간을 줄인다”는 가설을 먼저 확인해야 한다. 제작 담당자 3명 정도에게 기존 견적 작성 과정과 실제 변경 사례를 받아, 같은 사례의 작성 시간·누락 항목·재작업 횟수를 비교하는 것이 다음 제품 검증이다.

## 잘 구현한 부분

- 서버가 입력 규격을 검증하고 BOM·공임·가산액·세금을 다시 계산한다. 클라이언트가 보내는 가격을 믿지 않는다.
- SQLite 트랜잭션으로 현재 견적, 변경 스냅샷, 감사 기록을 함께 저장한다. 오래된 버전의 수정·상태 변경은 충돌로 거절한다.
- 수정하면 고객 검토 상태를 초안으로 되돌리고, 승인한 규격·금액은 잠근다. 승인 버전이 발주 기록 뒤에도 유지된다.
- 요청 원문, 업로드 자료, 완료한 생성·전사 작업을 견적 버전에 묶어 저장한다. 서버가 입력 파일과 완료 작업의 연결을 확인하고 경로·전사 결과를 확정한다.
- CSV 수식 주입을 방지하고, 업로드 형식·용량을 제한하며, 모델 미준비와 실제 추론 실패를 화면에 알린다.
- 이미지 시안과 치수 기반 구조 모델을 분리했다. 이미지 메시에서 제조 BOM을 추정하지 않는 판단은 옳다.

## 이번 리뷰에서 발견하고 보완한 부분

P1은 배포나 업무 적용 전에 반드시 해결할 문제, P2는 MVP 사용 중 잘못된 결과·상태를 만들 수 있는 문제, P3는 유지보수·확장 과제다. 공개 배포를 요청하지 않았으므로 배포 전 과제를 현재 로컬 실행의 실패로 계산하지 않는다.

| 우선순위 | 항목 | 근거와 영향 | 권장 조치 |
|---|---|---|---|
| P2 | 목표값과 증감량을 혼동하는 텍스트 해석 | `폭을 100cm로 줄여 주세요`, `선반 4개로 늘려 주세요`, `increase width to 1400mm`가 목표값 대신 증감량으로 해석되었다. 잘못된 규격 거절 또는 과다 변경을 유발한다. | `로/으로/to` 목표값과 `by/+` 증감량을 분리하고 한국어·영어 회귀 사례를 추가한다. |
| P2 | 늦게 도착한 미디어 작업이 다른 견적 화면에 반영될 수 있음 | 업로드·작업 시작·폴링 중 새 견적을 열어도 완료 응답을 적용하는 분기에 작업·화면 동일성 검사가 없었다. 다른 견적의 전사 또는 참고 시안이 표시될 수 있다. | 화면 세대 번호·작업 ID를 모든 비동기 경계에서 검사하고 견적 전환·이미지 제거 때 참조 상태를 초기화한다. |
| P2 | 상태 이력이 규격 저장으로 표시됨 | 저장소는 `sent/approved/ordered` 이벤트를 남기지만 화면은 `status`만 상태 변경으로 표시했다. 승인·발주 이력의 의미가 화면에서 사라졌다. | 저장소 이벤트 이름과 화면 라벨을 일치시킨다. |
| P2 | 이미지 시안과 원본 요청의 견적 연결이 없음 | 견적·버전 스냅샷에는 규격·BOM·금액만 저장된다. 화면의 이미지·작업 상태는 세션에 남아 새로고침 후 복원되지 않는다. | 견적 버전에 미디어 ID·생성 작업 ID·모델 정보·원문을 묶어 저장하고 잠금·재조회 정책을 함께 정의한다. |
| P2 | 반복 시안 교체 시 그래픽 자원 해제 누락 | GLTF를 교체할 때 geometry는 해제하지만 mesh 재료와 텍스처는 해제하지 않았다. 반복 생성·조회 시 브라우저 GPU 메모리가 누적될 수 있다. | 공유 CAD 재료와 시안별 재료를 구분하고 시안의 재료·텍스처를 중복 없이 해제한다. |
| P2 | 저장 필드와 변경 감지의 불일치 | 원문을 견적에 저장하도록 확장한 뒤에도 원문 타이핑·브라우저 음성 결과가 수정 상태를 만들지 않으면, 상태 변경이 새 원문을 덮어쓸 수 있다. | 저장 대상 필드의 모든 변경이 확인 체크를 해제하고 수정 상태를 만들도록 통일한다. |
| P2 | 미디어 처리 중 중복 입력·상태 변경 | 업로드 중 다른 필드 변경이 오디오 입력을 다시 활성화하거나, 모델 작업 중 상태 전환이 먼저 끝나면 입력·작업 연결이 사라질 수 있다. | 업로드·추론 중 오디오 중복 입력, 저장과 상태 전환을 함께 막는다. |
| P2 | WebGL 실패 시 완료 작업 상태가 남음 | 뷰어가 없을 때 이미지 작업 완료 분기가 로드 결과 없이 종료되면 저장이 계속 비활성화될 수 있다. | 뷰어 미준비 시 생성 실행을 막거나, 완료 자료를 기록한 뒤 작업 상태를 해제한다. |

위 표는 수정 전 원인과 영향을 기록한 것이다. 아래 최종 확인에서 각 항목에 반영된 조치를 설명한다. 제조 안전성·AI 품질과 소프트웨어 동작 검증은 서로 다른 검증이다.

## 공개 배포·실제 업무 적용 전에 필요한 일

1. **권한과 승인 증거 — P1.** 로그인, 회사·고객별 데이터 격리, 담당자와 승인자 역할, 승인자 ID·시각·승인 문서가 필요하다. 현재 상태 버튼은 단일 담당자의 로컬 기록이다. 출처 검사는 사용자 권한을 대신하지 않는다.
2. **제작 기준 — P1.** 제조 전문가와 표준 설계를 확정하고, 하중·처짐·접합·홀 위치·공차·전도 조건을 검증해야 한다. 40mm 프레임과 판 두께·보강 규칙은 시안용 가정이다. GLB는 삼각형 메시이며 가공용 STEP/CAD 도면이나 구조 안전성 증거가 아니다.
3. **실견적과 발주 객체 — P1.** 공급사별 자재 단가, 유효 기간, 가공·도장·물류비, 납기, 재고, 발주 행·취소·재발주·중복 방지가 필요하다. 현재 `ordered`는 견적 상태 기록이다. 현재 계산의 25%는 원가에 더하는 가산율이다. 원가 100에 25를 더해 판매가 125가 되면 판매가 대비 이익률은 20%이므로, 가격 용어도 이 기준으로 설명해야 한다.
4. **AI 품질 평가 — P2.** 실제 진열대 사진 5장 이상과 한국어 요청·음성 10개 이상으로 성공률, 치수 추출 오류, 지연, GPU 메모리, 비용을 기록한다. 공식 예제 한 개와 영어 음성의 추론 성공은 한국어 제작 요청 정확도를 입증하지 않는다.
5. **운영·복구 — P2.** 업로드·작업 보존 기간, 삭제 정책, 저장 용량 제한, SQLite 백업·복구, 모델 오류의 구조화, 작업 재시도·취소·중복 처리, 모델 준비 상태 갱신을 설계한다.
6. **재현 가능한 환경 — P3.** 모델 저장소의 고정 버전·해시, 설치 순서, 전이 의존성, 라이선스 목록을 관리한다. 현재 공식 모델 실행기를 연결한 선택은 좋지만 다른 PC에서 설치·추론되는지도 별도로 확인해야 한다.

## 검증의 의미와 한계

- 도메인·HTTP 테스트는 계산 정합성, 입력 거절, 상태 전이, 버전 충돌, 이력 보존, CSV 보호를 확인하는 근거다.
- API 스모크의 모델 미준비 경로 통과와 실제 모델 추론 성공은 별도 결과다. `ready:true`만으로 추론 성공을 판단하지 않는다.
- 브라우저 스모크는 화면 입력·저장·상태 변경·내보내기가 연결되는지 확인해야 한다. 코드나 HTML에 버튼이 존재하는 것만으로 통과 처리하지 않는다.
- 실제 모델 스모크의 GLB 재로딩·유한한 좌표·면 개수·전사 문장 확인은 출력이 생성됐다는 근거다. 외형의 품질, 치수 정확도, 제조 적합성을 보장하지 않는다.
- 이 리뷰는 공개 배포 보안 감사, 제조 구조 검토, 실제 고객 조사나 한국어 인식 성능 평가를 대신하지 않는다.

## 최종 확인

최신 소스 검토에서 위 8개 원인에 대한 보완을 확인했다.

| 항목 | 반영한 조치 | 확인 근거 |
|---|---|---|
| 텍스트 목표값 | `로/으로/to` 목표값과 증감량을 구분했다. | `server/domain.mjs`의 `explicitTarget`와 관련 한국어·영어 도메인 사례. 직접 실행에서 `폭 140cm로 늘려줘` → 1400mm, `선반 2개로 줄여 주세요` → 2개를 확인했다. |
| 비동기 작업 격리 | 화면·이미지 세대 번호와 현재 작업 ID를 업로드·시작·폴링·GLTF 로드 뒤에 검사한다. 견적 전환 시 뷰어 참조도 지운다. | `src/main.js`의 `resetMediaState`, `pollAudioJob`, `pollJob`, `src/viewer.js`의 `loadReference`. |
| 상태 이력 | `sent/approved/ordered`를 고객 검토·승인·발주 라벨로 표시한다. | `src/main.js`의 `renderHistory`. |
| 원본과 견적 연결 | 원문·이미지·생성 작업·오디오·전사를 버전·감사 기록에 보존하고 승인 후 잠근다. 이전 SQLite 스키마에 컬럼을 추가하는 이전 처리도 있다. | `server/media.mjs`의 `resolveSources`, `server/app.mjs`의 `canonicalSources`, `server/storage.mjs`의 `sources_json`, 관련 도메인·HTTP 사례. |
| 그래픽 자원 | 시안별 재료·텍스처를 중복 없이 해제하며 취소된 늦은 로드의 자원도 정리한다. | `src/viewer.js`의 `disposeReferenceGroup`, `clearReference`, `loadReference`. 장시간 GPU 메모리 안정성을 측정한 결과는 아니다. |
| 저장 필드 변경 감지 | 원문 타이핑, 브라우저 음성 결과, 파일 전사와 이미지 변경이 수정 상태를 만든다. | `src/main.js`의 입력 이벤트와 `markDirty`. |
| 작업 중 입력·상태 변경 | 오디오 업로드 중 중복 입력을 막고, 미디어 작업 중 견적 저장·상태 전환을 함께 비활성화한다. | `src/main.js`의 `refreshSaveState`, 오디오 업로드 이벤트. |
| WebGL 실패 | 뷰어가 준비되지 않으면 이미지 생성 버튼을 비활성화한다. | `src/main.js`의 `refreshImageState`. |

선반 사이 간격에 40mm 가로 프레임 높이를 반영한 검증과, 선택한 선반 재료와 별개로 모든 프레임을 강재로 표시하는 수정도 확인했다. 화면의 금액 설명은 데모 단가·견적 가산액으로 맞췄다.

실행 결과는 `docs/verification/api-smoke.json`, `docs/verification/browser-smoke.json` 및 작업 기록의 최종 결과를 기준으로 확인한다. `scripts/browser-smoke.mjs`의 지연 오디오 시나리오는 응답을 통제해 화면 간 오염을 검사하는 테스트이며 실제 Whisper 추론을 증명하지 않는다. 실제 모델 추론 결과는 `model-service/smoke-output/report.json`에 별도로 기록한다. 이 문서는 소스 검토와 직접 실행한 해석 사례를 기록하며, 개별 검사 통과 횟수·추론 산출값은 각 검증 보고서에서 관리한다.

이번 소스 검토에서 로컬 MVP를 즉시 막는 미해결 P1은 확인하지 못했다. 공개 배포·실제 제조에 필요한 P1과 제품 품질 평가 과제는 위 목록에 남아 있다. 이 판단은 검토 범위에 한정되며 알려지지 않은 오류가 없다는 보증은 아니다.

## 면접에서 설명할 핵심

“AI로 외형을 참고하고, 확인한 규격으로 서버가 BOM과 견적을 계산합니다. 변경과 승인에 버전을 두어 오래된 화면이나 승인 후 수정이 금액을 바꾸지 못하도록 설계했습니다.” 이 설명을 실제 저장·충돌·승인 시연으로 증명하면 AI·백엔드·업무 시스템 역량이 연결된다. 다음 개발 우선순위는 **실제 제작 규칙, 실단가, 승인 권한, 대표 입력의 검증 자료**다.
